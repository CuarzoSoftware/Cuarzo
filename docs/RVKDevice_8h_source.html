189 // Fence-tracked deferred destruction: cleanup runs once its fence signals (drained by
190 // clearGarbage()). Lets submissions be async without freeing in-flight resources. Each entry
191 // records the thread that created the resources; cleanup MUST run on that same thread because
192 // Vulkan command pools require external synchronization (NVIDIA crashes on cross-thread
193 // destruction that Mesa tolerates). clearGarbage() therefore only drains the caller thread's
194 // entries.
195 struct Garbage
196 {
197 VkFence fence;
198 std::function<void()> cleanup;
199 std::thread::id owner;
200 };
