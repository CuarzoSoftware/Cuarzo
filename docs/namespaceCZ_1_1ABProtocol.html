Detailed Description

Wire protocol between the library (ABRemoteBackend) and the service (ABServer).

Transport: a SOCK_SEQPACKET Unix socket (message boundaries are kept, fds travel with SCM_RIGHTS). Every message starts with an Op. Requests are answered in order, and the server never sends unsolicited messages.

  • Hello (client → server): first message, carries the protocol version.
  • HelloReply (server → client): the server's version. The client disconnects if it differs.
  • Load (client → server): rasterize a file fitted in a box, for a DRM device. Followed by the path bytes (not NUL terminated).
  • LoadIcon (client → server): look up an icon (the parameters of XDGIconThemeManager::findIcon(), see ABIconKey) and rasterize it fitted in a box, for a DRM device. Followed by the app id, the names and then the themes, each NUL terminated.
  • Generate (client → server): draw a generated asset (see ABGenerators), for a DRM device. Followed by the generator name and the strings (each NUL terminated), then the ints (Int64 each).
  • LoadReply (server → client): the result (of Load, LoadIcon or Generate). On success its fds are the DMA-buf planes, plus a sync_file (write fence) if hasFence. Each successful LoadReply adds a reference to assetId for this client.
  • Release (client → server): drops one reference per id. Followed by the ids.

All the references of a client are dropped when it disconnects.
