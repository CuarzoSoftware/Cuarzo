AssetBroker

Overview

Icon and image loading shared between apps as DMA-bufs.

Shared icon and asset loading, optionally served across processes.

Header#include <CZ/AssetBroker/ABCore.h>
pkg-configcz-asset-broker
Mesondependency('cz-asset-broker')
Depends onCore, Ream, XDGKit

Assets (icons, SVGs and images) are either generated in each app or, when the cz-asset-broker service is running, generated once by the service and shared with every app as DMA-bufs, so apps use the same GPU buffers. Requesting the same icon, size and device again returns the same RImage while some copy of it is alive.

Main Classes

  • ABCore loads icons (described by a ABIconKey) and images, in-process or through the service depending on its mode (ABMode::Auto, Local or Remote).
  • ABCore::IconProvider() plugs icons into Kay's image nodes.
  • ABServer is the service; the ABProtocol namespace documents its wire protocol, and ABGenerators the assets it can generate.

Apps load icons and images through ABCore. Depending on the ABMode, the assets are either generated in-process (ABMode::Local) or requested from the cz-asset-broker service (ABMode::Remote), which hands them out as DMA-bufs so every app shares the same GPU buffers. ABMode::Auto (the default) uses the service when available and falls back to local loading.
